# 다음무대 프로토타입

팝업과 축제 설치물을 철거할 때 나오는 자재(가벽, 합판, 아크릴, 비계 파이프, 현수막, 조명, 집기)를 기록하고,
다음 팝업이나 동네 작가에게 보내는 AI 순환 서비스의 클릭 시연판이다.
남은 재료는 다음 해 크리에이티브X성수 주제전시('창조적 변용')의 작품이 되고, 관람객은 작품 QR로 재료가 지나온 길을 본다.

- 모바일 웹, 기준 너비 390px (320~430px에서 가로 스크롤 없음). 데스크톱에서는 가운데 폰 너비 칼럼으로 보인다.
- 서버 없음. 상태는 메모리에만 있고 새로고침하면 처음으로 돌아간다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입 검사 + dist 생성
npm run preview    # dist를 http://localhost:4173 으로 띄움
```

Node 20.19 이상. 의존성은 react, react-dom, vite, @vitejs/plugin-react, typescript 다섯 개이고 버전을 고정했다.
글꼴은 Pretendard(jsDelivr CDN)를 쓴다.

## 화면 바로가기 `?s=`

슬라이드 캡처용으로 주소만으로 각 화면을 준비된 상태로 연다. 예: `http://localhost:4173/?s=result`

| 키 | 화면 | 흐름 |
|---|---|---|
| `home` | 시작. 역할 4개, 시연 순서대로 보기 | - |
| `register` | 철거 등록 (예시 값이 채워진 양식, 사진 고르기) | 1 팝업 운영사 |
| `analyzing` | AI 분석 진행 (영역 분할 → 분류 → 크기·무게 추정) | 1 |
| `result` | 분석 결과: 사진 위 인식 상자, 자재 목록, 수량 고치기·빼기 | 1 |
| `lab` | 실제 AI 분석: 브라우저에서 CLIP 모델로 사진 9칸 분류 | 1 |
| `done` | 등록 완료: 수거 일정, 예상 감축량, 감축 확인서 미리보기 | 1 |
| `find` | 자재 찾기: 목록, 종류 칩, 목록/지도 전환 | 2 작가·다음 팝업 |
| `match` | AI 추천: 문장으로 요청, 일치도 순위와 이유 | 2 |
| `item` | 자재 상세와 신청 시트 | 2 |
| `applied` | 신청 완료와 수령 안내 | 2 |
| `journey` | 재료의 지도 (작품 QR로 여는 밤 화면) | 3 관람객 |
| `dashboard` | 성동구 대시보드 | 4 성동구 |

함께 쓸 수 있는 값

| 값 | 쓰는 곳 | 뜻 |
|---|---|---|
| `photo=installation` / `banner` / `popup` | register, analyzing, result, lab, done | 처음 고를 예시 사진 (기본 installation) |
| `hold=1` / `2` / `3` | analyzing | 그 단계에서 멈춰 둔다 (캡처용). 없으면 3.6초 뒤 결과로 넘어감 |
| `view=map` | find | 지도 보기로 연다 (창고 핀이 열린 상태) |
| `id=<자재 id>` | item, applied | lumber, plywood, table, scaffold, acrylic, cube, banner, curtain, flood, ledbar, shelf, stool, pedestal, steel |
| `q=<문장>` | match | 추천 요청 문장 |
| `m=plywood` / `scaffold` / `banner` / `acrylic` / `flood` | journey | 그 재료의 경로와 이력을 펼친 상태 |
| `tour=1` | 모든 화면 | 위쪽에 시연 순서 표시를 켠다 |

예: `?s=result&photo=popup`, `?s=analyzing&hold=2`, `?s=find&view=map`, `?s=journey&m=scaffold`

## 무엇이 실제이고 무엇이 시연용인가

| 부분 | 상태 |
|---|---|
| 실제 AI 분석 (`lab`) | **실제로 돈다.** transformers.js로 CLIP 모델을 브라우저에서 실행해 사진 3×3 칸마다 자재 이름 19개 중 가장 가까운 것을 고른다. 점수도 모델 출력 그대로다 |
| 대시보드의 생활인구 곡선 | **실제 공공데이터.** 서울시 행정동 생활인구(OA-14991), 성수 4개 동 합계, 2025 축제 주말(9.20~21)과 같은 기간 평소 주말 10일의 시간대별 평균 |
| 대시보드의 점포 교체율 문장 | **실제 공공데이터.** 상권분석서비스(OA-22172) 2025년 등록 점포 교체율((개업+폐업)÷점포 수) 성수 21.5%, 서울 20.1%. 팝업은 이 통계에 없음 |
| 분석 진행·결과 화면 (YOLOv8-seg, CLIP, Depth Anything V2) | 시연용. 예시 사진 3장의 상자 위치와 자재 목록을 미리 만들어 두고 순서대로 보여 준다. 직접 올린 사진은 예시 목록을 쓴다 |
| AI 추천 (multilingual-E5 + 거리·일정) | 시연용. 같은 모양의 결과가 나오도록 키워드 규칙으로 점수를 흉내 낸다. 요청 문장의 종류·길이·수량·날짜는 실제로 읽어서 반영한다 |
| 주별 철거량 LightGBM 예측, KPI, 자재 구성, 거리 순위 | 시연용 예시 데이터 |
| 자재 목록, 팝업 이름, 작가, 작품, 이력, 확인서 | 시연용 예시. 팝업은 실제 브랜드가 아닌 '향수 브랜드 팝업' 같은 일반 이름을 쓴다 |
| 감축량 | 재사용 1kg당 1.6kgCO₂e로 계산한 시연용 추정치 |

### 실제 AI 분석 자세히

- 라이브러리: `@huggingface/transformers` 3.7.6. 버튼을 누를 때만 jsDelivr에서 불러온다(`src/lab/clip.ts`). npm 의존성에는 넣지 않았다
- 모델: `Xenova/clip-vit-base-patch32` ONNX 8비트 양자화(149MB), WebAssembly로 실행. 처음 한 번 라이브러리와 실행 엔진을 합쳐 약 180MB를 내려받는다
- 내려받은 파일은 브라우저 Cache Storage(`transformers-cache`)에 저장돼 두 번째부터는 바로 시작한다
- 사진은 기기 밖으로 나가지 않는다. 9칸 각각과 사진 전체를 한 번씩, 모두 10번 추론한다
- 실패하면(오프라인, 느린 연결, 지원하지 않는 브라우저) 이유를 보여 주고 '예시 결과로 계속'으로 흐름을 이어 간다. 진행 중에는 '그만하기'로 멈출 수 있다
- 확인한 것: 헤드리스 Microsoft Edge 156(이 노트북)에서 끝까지 실행됨. 첫 실행은 모델 내려받기 약 8초 + 추론 10번 4.4초, 두 번째 실행은 캐시에서 불러와 추론 10번 4.2초.
  주제전시 사진에서는 원목 테이블 64%, 로봇팔 86%, 비계 파이프 35% 같은 결과가 나왔다
- 한계: 칸 단위로 보기 때문에 경계에 걸친 물체는 틀릴 수 있다. 실제 서비스에서는 영역 분할(YOLOv8-seg)을 먼저 하고 영역마다 분류한다

## 디자인 토큰

색, 글자 크기, 간격, 모서리, 그림자, 움직임 값은 모두 `src/styles/tokens.css`의 `--dm-*` 변수에만 있다.
다른 CSS와 SVG 그림은 변수만 참조하므로 스킨을 바꿀 때는 이 파일만 고치면 된다.
차트 색은 대비와 색약 구분 검사를 통과한 값이다.

## 폴더

```
src/
  styles/tokens.css     디자인 토큰
  styles/*.css          기본, 부품, 화면, 재료의 지도
  lib/app.tsx           화면 이동(?s=), 시연 순서, 메모리 상태
  data/                 예시 사진의 인식 결과, 자재 목록, 지도 좌표, 대시보드, 공공데이터
  lab/clip.ts           브라우저 CLIP 분류
  components/           머리글, 등급 배지, 인식 상자, 성수동 약도, 자재 그림
  screens/              화면 12개
screenshots/            390px 화면 캡처 (full/은 전체 길이)
```
